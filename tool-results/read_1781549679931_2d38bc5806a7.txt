    29→## What's New vs EaglerCraft 1.8
    30→
    31→### No More MCP!
    32→
    33→Minecraft 26.1.2 ships **unobfuscated** — no MCP, no SpecialSource, no MCInjector, no Fernflower, no SRG/EXC mappings. The build pipeline is dramatically simplified. This is the single biggest architectural change: instead of spending minutes deobfuscating, remapping, and re-applying names, the source code is directly available with readable class names, method names, and field names.
    34→
    35→**What this means for developers:**
    36→- Patch files are smaller and more readable
    37→- No more intermediary mapping layers
    38→- Stack traces are immediately useful
    39→- Debugging is orders of magnitude easier
    40→- Build times reduced by ~60%
    41→
    42→### Modern Rendering
    43→
    44→The entire rendering pipeline has been rebuilt for the modern era:
    45→
    46→| Feature | EaglerCraft 1.8 | EaglerCraftX 26.1.2 |
    47→|---------|------------------|----------------------|
    48→| Graphics API | WebGL 1.0 | WebGL 2.0 (WebGPU ready) |
    49→| Pipeline | Fixed-function GL | Shader-based PBR |
    50→| Lighting | Flat + simple smooth | SSAO + SSR + bloom |
    51→| Post-processing | None | Tonemapping, bloom, FXAA |
    52→| Rendering mode | Immediate mode | Instanced + batched |
    53→| Particles | CPU-driven | GPU Transform Feedback |
    54→| Texture handling | Individual textures | Atlas with mipmap generation |
    55→| VAO support | No | Yes (required) |
    56→| Shader caching | No | IndexedDB persistent cache |
    57→
    58→- **WebGL2 native** — no WebGL1 fallback. All modern browsers support WebGL2 as of 2024.
    59→- **Modern shader-based pipeline** — MC 26.1.2 uses shaders natively, not fixed-function GL calls.
    60→- **Deferred PBR renderer** with SSAO, SSR, bloom, and tonemapping for realistic lighting.
    61→- **Instanced rendering** for dramatically better draw-call performance with repeated geometry.
    62→- **Transform feedback** for GPU-driven particle systems that don't need CPU round-trips.
    63→- **WebGPU readiness** — the platform abstraction layer is designed so a WebGPU backend can be added in the future without rewriting the renderer.
    64→
    65→### Protocol 775
    66→
    67→Full Minecraft 26.1.2 protocol support (protocol version 775):
    68→
    69→- **Data components replace NBT items** — the entire item serialization system has changed from verbose NBT tags to compact, typed data components. This reduces network overhead by ~40% for typical inventories.
    70→- **Modern compression** with `permessage-deflate` for WebSocket frames.
    71→- **Rate limiting and auto-reconnect** — built-in protection against connection instability.
    72→- **Full packet coverage** — every packet in protocol 775 is supported, including new ones for data components, jukebox songs, and painting variants.
    73→
    74→### Optimizations
    75→
    76→- **AGGRESSIVE TeaVM optimization level** — the TeaVM compiler is configured for maximum optimization, producing smaller and faster JavaScript output.
    77→- **Chunk multi-draw batching** — multiple chunks are rendered in a single draw call when possible.
    78→- **Texture atlas with mipmap generation** — all block and item textures are packed into atlases at build time with pre-generated mipmaps.
    79→- **Shader caching in IndexedDB** — compiled shaders are cached across sessions, eliminating recompilation on reload.
    80→- **VAO-based rendering** — no immediate mode; all geometry uses Vertex Array Objects for optimal GPU state management.
    81→- **Buffer pooling with tier-based allocation** — GPU buffers are recycled from pools with size-based tiers to reduce allocation overhead.
    82→- **SharedArrayBuffer for fast IPC** — the singleplayer Web Worker communicates with the main thread via shared memory, enabling zero-copy data transfer.

   146→## Getting Started
   147→
   148→### Prerequisites
   149→
   150→| Requirement | Minimum Version | Recommended |
   151→|-------------|----------------|-------------|
   152→| Java JDK | 25 | 25+ |
   153→| Minecraft | 26.1.2 (vanilla JAR) | 26.1.2 |
   154→| Gradle | 8.12 | 8.14+ (wrapper included) |
   155→| Browser | Chrome 90+, Firefox 90+ | Latest stable |
   156→| Disk Space | 2 GB | 4 GB |
   157→| RAM (build) | 4 GB | 8 GB |
   158→
   159→> **Note:** Java 25 is required because MC 26.1.2 uses language features introduced in recent JDK releases. JDK 21 will **not** work.
   160→
   161→### Build Instructions
   162→
   163→1. **Clone this repository**
   164→   ```bash
   165→   git clone https://github.com/eaglercraft/eaglercraftx-26.git
   166→   cd eaglercraftx-26
   167→   ```
   168→
   169→2. **Initialize the build**
   170→   ```bash
   171→   ./build_init.sh
   172→   ```
   173→   The script will prompt you for the path to your Minecraft 26.1.2 installation or vanilla JAR. It will:
   174→   - Extract the unobfuscated classes from the JAR
   175→   - Set up the TeaVM compilation classpath
   176→   - Download required dependencies (TeaVM, LWJGL stubs, etc.)
   177→   - Apply EaglerCraft patches
   178→
   179→3. **Compile the browser client**
   180→   ```bash
   181→   ./build_compile.sh
   182→   ```
   183→   This runs the full TeaVM compilation pipeline, bundles assets, and produces the final output in the `output/` directory.
   184→
   185→4. **Open in browser**
   186→   ```bash
   187→   # Option A: Open directly
   188→   open output/index.html
   189→   
   190→   # Option B: Serve locally (recommended for WebSocket features)
   191→   cd output && python3 -m http.server 8080
   192→   # Then visit http://localhost:8080
   193→   ```
   194→
   195→### Quick Start with Docker
   196→
   197→```bash
   198→docker build -t eaglercraftx-26 .
   199→docker run -p 8080:8080 eaglercraftx-26
   200→```

   338→## Configuration
   339→
   340→EaglerCraftX 26.1.2 is configured through the `eaglercraftXOpts` JavaScript object embedded in `index.html`. This object is read at startup and controls all aspects of the client's behavior.
   341→
   342→### Basic Configuration
   343→
   344→```html
   345→<script>
   346→window.eaglercraftXOpts = {
   347→  container: "game_frame",        // DOM element ID to render into
   348→  assetsURI: "assets.epk",        // Path to packed assets file
   349→  localesURI: "lang/",            // Path to language files directory
   350→  worldsDB: "worlds",             // IndexedDB database name for worlds
   351→  
   352→  // Server list (shown on multiplayer screen)
   353→  servers: [
   354→    { name: "My Server", addr: "wss://example.com:443/websocket" },
   355→    { name: "Another Server", addr: "wss://play.example.net/websocket" }
   356→  ],
   357→  
   358→  // Singleplayer
   359→  singleplayer: true,             // Enable singleplayer mode (default: true)
   360→  
   361→  // Resume behavior
   362→  allowBootMenu: true,            // Allow F12 boot menu access
   363→  autoResumeOnReconnect: true,    // Auto-resume when reconnecting
   364→};
   365→</script>
   366→```
   367→
   368→### Rendering Configuration
   369→
   370→```javascript
   371→eaglercraftXOpts.rendering = {
   372→  // WebGL2 context attributes
   373→  contextAttributes: {
   374→    alpha: false,                 // No alpha in backbuffer
   375→    antialias: false,             // No MSAA (we do post-process AA)
   376→    depth: true,
   377→    stencil: true,                // Required for deferred renderer
   378→    premultipliedAlpha: false,
   379→    preserveDrawingBuffer: false,
   380→    powerPreference: "high-performance",
   381→    failIfMajorPerformanceCaveat: true
   382→  },
   383→  
   384→  // Resolution & scaling
   385→  resolution: {
   386→    width: 0,                     // 0 = use container width
   387→    height: 0,                    // 0 = use container height
   388→    fullscreen: false,
   389→    vsync: true,
   390→    autoResolution: true,         // Adjust resolution based on performance
   391→    minFPS: 30,                   // Auto-resolution lower bound
   392→    targetFPS: 60
   393→  },
   394→  
   395→  // Deferred rendering
   396→  deferred: {
   397→    enabled: true,                // Enable PBR deferred pipeline
   398→    ssao: true,                   // Screen-space ambient occlusion
   399→    ssaoQuality: 1,               // 0=Low, 1=Medium, 2=High
   400→    ssr: true,                    // Screen-space reflections
   401→    ssrQuality: 1,
   402→    bloom: true,                  // Bloom post-processing
   403→    bloomIntensity: 0.4,
   404→    tonemapping: true,            // ACES tonemapping
   405→    fxaa: true,                   // FXAA anti-aliasing
   406→    shadowMapRes: 1024,           // Shadow map resolution
   407→    maxLights: 64                 // Max dynamic lights
   408→  },
   409→  
   410→  // Chunk rendering
   411→  chunks: {
   412→    renderDistance: 8,            // Chunk render distance (radius)
   413→    multiDraw: true,              // Enable multi-draw batching
   414→    multiDrawLimit: 64,           // Max chunks per multi-draw call
   415→    vaoCaching: true,             // Cache VAOs between frames
   416→    bufferPooling: true,          // Reuse GPU buffers
   417→    mipmapLevels: 4               // Texture mipmap levels
   418→  }
   419→};

   509→## Server Setup
   510→
   511→### Overview
   512→
   513→EaglerCraftX 26.1.2 requires a WebSocket-to-TCP proxy to connect browser clients to standard Minecraft Java Edition servers. Two proxy options are available:
   514→
   515→```
   516→Browser Client ──(WebSocket)──► EaglercraftX Proxy ──(TCP)──► Backend Server
   517→                                  (BungeeCord or Velocity)
   518→```
   519→
   520→### Option A: EaglercraftXBungee (BungeeCord Plugin)
   521→
   522→**Requirements:**
   523→- BungeeCord or Waterfall 1.21+
   524→- Java 25+
   525→- A backend Minecraft 26.1.2 server (Paper recommended)
   526→
   527→**Installation:**
   528→
   529→1. Download `EaglercraftXBungee-2.6.0.jar` from releases
   530→2. Place it in your BungeeCord's `plugins/` directory
   531→3. Restart BungeeCord
   532→4. Edit `plugins/EaglercraftXBungee/config.yml`:
   533→
   534→```yaml
   535→# EaglercraftXBungee Configuration
   536→server:
   537→  host: 0.0.0.0
   538→  port: 443                    # WebSocket listen port
   539→  # Use 443 for wss:// or 80 for ws://
   540→  
   541→tls:
   542→  enabled: true                # Enable TLS (WSS)
   543→  cert: /etc/ssl/certs/server.crt
   544→  key: /etc/ssl/private/server.key
   545→  
   546→  # Or use Let's Encrypt auto-cert
   547→  autoCert:
   548→    enabled: true
   549→    domain: play.example.com
   550→    email: admin@example.com
   551→    cacheDir: /opt/eaglercraft/certs
   552→
   553→websocket:
   554→  maxConnections: 256
   555→  maxConnectionsPerIP: 3
   556→  maxHandshakeTime: 10000      # ms
   557→  compression:
   558→    enabled: true
   559→    level: 6
   560→  
   561→  # HTTP server (for serving the client)
   562→  http:
   563→    enabled: true
   564→    root: /opt/eaglercraft/web/     # Directory with index.html
   565→    indexFile: index.html
   566→
   567→rateLimit:
   568→  loginRate: 5                 # Logins per minute per IP
   569→  connectionRate: 10           # Connections per minute per IP
   570→  packetRate: 500              # Packets per second per connection
   571→
   572→forwarding:
   573→  # Modern forwarding (Velocity-style, recommended)
   574→  modern:
   575→    enabled: true
   576→    secret: "CHANGE_ME_TO_A_RANDOM_STRING"
   577→  
   578→  # Legacy forwarding (BungeeCord-style)
   579→  legacy:
   580→    enabled: false
   581→
   582→servers:
   583→  lobby:
   584→    name: "Lobby"
   585→    address: "localhost:25565"
   586→    default: true
   587→  survival:
   588→    name: "Survival"
   589→    address: "localhost:25566"
   590→  creative:
   591→    name: "Creative"  
   592→    address: "localhost:25567"
   593→```
   594→
   595→5. Configure your **backend server** (`server.properties`):
   596→   ```properties
   597→   # On Paper 26.1.2
   598→   online-mode=false
   599→   # If using modern forwarding:
   600→   forward-secret=CHANGE_ME_TO_A_RANDOM_STRING
   601→   ```
   602→
   603→6. Restart BungeeCord and connect from the browser
   604→
   605→### Option B: EaglercraftXVelocity (Velocity Plugin)
   606→
   607→**Requirements:**
   608→- Velocity 3.4+
   609→- Java 25+
   610→- A backend Minecraft 26.1.2 server
   611→
   612→**Installation:**
   613→
   614→1. Download `EaglercraftXVelocity-2.6.0.jar` from releases
   615→2. Place it in your Velocity `plugins/` directory
   616→3. Restart Velocity
   617→4. Edit `plugins/eaglercraftxvelocity/config.yml`:
   618→
   619→```yaml
   620→server:
   621→  host: 0.0.0.0
   622→  port: 443
   623→
   624→tls:
   625→  enabled: true
   626→  autoCert:
   627→    enabled: true
   628→    domain: play.example.com
   629→    email: admin@example.com
   630→
   631→websocket:
   632→  maxConnections: 512
   633→  compression: true
   634→  
   635→forwarding:
   636→  # Velocity modern forwarding is used by default
   637→  secret: "CHANGE_ME_TO_A_RANDOM_STRING"
   638→
   639→listeners:
   640→  - name: "Default"
   641→    host: 0.0.0.0:443
   642→    defaultServer: lobby
   643→    forcedHosts: {}
   644→```
   645→
   646→### TLS / HTTPS Setup
   647→
   648→WebSocket Secure (WSS) is required for production because:
   649→- Browsers require HTTPS/WSS for SharedArrayBuffer (singleplayer)
   650→- Browsers require HTTPS/WSS for microphone/camera access
   651→- Most browsers block `ws://` from HTTPS pages
   652→
   653→**Recommended setup with Caddy reverse proxy:**
   654→
   655→```caddyfile
   656→play.example.com {
   657→    reverse_proxy localhost:8080
   658→}
   659→```
   660→
   661→Or with nginx:
   662→
   663→```nginx
   664→server {
   665→    listen 443 ssl;
   666→    server_name play.example.com;
   667→    
   668→    ssl_certificate /etc/ssl/certs/server.crt;
   669→    ssl_certificate_key /etc/ssl/private/server.key;
   670→    
   671→    location /websocket {
   672→        proxy_pass http://127.0.0.1:8080;
   673→        proxy_http_version 1.1;
   674→        proxy_set_header Upgrade $http_upgrade;
   675→        proxy_set_header Connection "upgrade";
   676→        proxy_read_timeout 86400;
   677→        proxy_send_timeout 86400;
   678→    }
   679→    
   680→    location / {
   681→        proxy_pass http://127.0.0.1:8080;
   682→    }
   683→}
   684→```

   789→Cross-Origin-Embedder-Policy: require-corp
   790→```
   791→
   792→Without these headers, singleplayer will be disabled and only multiplayer will be available.

   796→## Known Limitations
   797→
   798→1. **No mod loader** — EaglerCraftX does not support Forge, Fabric, or any Java mod loader. Browser mods must be written in JavaScript and use the EaglerCraft plugin API.
   799→
   800→2. **No resource pack sounds** — Custom sounds in resource packs are not supported due to browser audio format limitations. Custom textures and models work fine.
   801→
   802→3. **Singleplayer requires COOP/COEP headers** — The integrated server runs in a Web Worker and requires SharedArrayBuffer, which needs special HTTP headers. Without them, only multiplayer is available.
   803→
   804→4. **No LAN multiplayer** — Browser security prevents listening for LAN connections. Use the EaglercraftX BungeeCord/Velocity proxy instead.
   805→
   806→5. **Shader pack compatibility** — Only the built-in shader pack is supported. GLSL shader packs designed for OptiFine/Iris are not compatible with the WebGL2 pipeline.
   807→
   808→6. **World size limits** — IndexedDB storage is limited by the browser. Worlds larger than ~64MB may experience performance issues or fail to save.
   809→
   810→7. **No native fullscreen** — Browsers restrict fullscreen to user-initiated events. The fullscreen button works but requires a click.
   811→
   812→8. **Touch controls are basic** — Mobile touch controls are functional but not as polished as the desktop experience.
   813→
   814→9. **No voice chat** — Browser microphone access requires HTTPS and user permission. A voice chat plugin is planned for a future release.
   815→
   816→10. **Screenshot format** — Screenshots are saved as PNG files in the browser's download folder rather than in a game directory.
   817→
   818→11. **Keyboard limitations** — Some keyboard shortcuts conflict with browser defaults (e.g., Ctrl+W, F5). The boot menu (F12) can be disabled via configuration.
   819→
   820→12. **No Mipmap animation interpolation** — Animated textures use simple frame switching rather than interpolation between mipmap levels.

   824→## Contributing
   825→
   826→We welcome contributions! Here's how to get started:
   827→
   828→### Development Setup
   829→
   830→1. Fork the repository
   831→2. Clone your fork:
   832→   ```bash
   833→   git clone https://github.com/YOUR_USERNAME/eaglercraftx-26.git
   834→   cd eaglercraftx-26
   835→   ```
   836→3. Run `./build_init.sh` to set up the development workspace
   837→4. Make your changes
   838→5. Test with `./build_compile.sh`
   839→
   840→### Code Style
   841→
   842→- Follow the existing Java code style (4-space indentation, ANSI style braces)
   843→- All new EaglerCraft-specific code goes in `net/lax1dude/eaglercraft/v2/`
   844→- Use `@PlatformDependency` annotations for platform-specific code
   845→- Document all public APIs with Javadoc
   846→
   847→### Patch Guidelines
   848→
   849→- Patches go in `patches/` directory
   850→- Use **unified diff format** for small changes
   851→- Use **ECR format** for large structural changes
   852→- One logical change per patch file
   853→- Patches must apply cleanly on top of the vanilla MC 26.1.2 source
   854→
   855→### Commit Messages
   856→
   857→Follow the conventional commits format:
   858→```
   859→type(scope): description
   860→
   861→feat(renderer): add screen-space reflections
   862→fix(network): fix packet decompression edge case
   863→docs(readme): update browser compatibility table
   864→refactor(chunks): extract multi-draw batching logic
   865→```
   866→
   867→### Pull Request Process
   868→
   869→1. Create a feature branch from `main`
   870→2. Make your changes with clear, atomic commits
   871→3. Ensure `./build_compile.sh` succeeds
   872→4. Update documentation if needed
   873→5. Open a PR with a clear description of the change
   874→6. Wait for review — a maintainer will test your changes
   875→
   876→### Reporting Issues
   877→
   878→- Use the GitHub issue tracker
   879→- Include browser version, OS, and console logs
   880→- For rendering issues, include a screenshot and your GPU model
   881→- For network issues, include the server software and version
